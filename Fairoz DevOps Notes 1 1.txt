---------------- nohup Command ----------------

nohup = "no hang up"

Used to run long-running processes without stopping when terminal closes.

Example:

nohup pnpm dev > app-log-$(date -u +%Y%m%d%H).log 2>&1 &


Explanation:

nohup → run command even after logout

pnpm dev → command being executed

> → redirect output

app-log-$(date ...).log → log file with timestamp

2>&1 → redirect errors to same log file

& → run in background

-------------------- SonarQube --------------------

How to Install SonarQube on Windows and Run It in Background

1. Download SonarQube from the official website.

2. Open CMD and navigate to the installation directory, for example:

3. sonarqube-x.x.x\bin\windows-x86-64


4. nstall SonarQube as a Windows Service:

SonarService.bat install


5. Close the Command Prompt window.

6. Reopen Command Prompt as Administrator (Right-click → Run as administrator).

7. Navigate again to the SonarQube Windows binaries folder:

cd C:\Path\To\SonarQube\sonarqube-x.x.x\bin\windows-x86-64


8. Start the SonarQube service:

net start SonarQube


9. Or open Windows Services and start the SonarQube service manually.

-------------------- Extract SSL Certificate via OpenSSL --------------------

echo | openssl s_client -connect <IP>:<PORT> -servername <IP> | \
sed -ne '/-BEGIN CERTIFICATE-/,/-END CERTIFICATE-/p' > server-cert.crt


Copy certificate to trusted anchors:

sudo cp server-cert.crt /etc/pki/ca-trust/source/anchors/


Import certificate into Java keystore:

sudo keytool -import -trustcacerts \
-file /etc/pki/ca-trust/source/anchors/server-cert.crt \
-alias generic-cert \
-keystore /usr/lib/jvm/java-17-amazon-corretto/lib/security/cacerts \
-storepass changeit

-------------------- Elastic Beanstalk Deployment Strategies --------------------

1. All at once

Fastest deployment

Application has downtime

Good for development

No extra cost

Flow:

v1 --> stop --> v2
v1 --> stop --> v2
v1 --> stop --> v2
v1 --> stop --> v2

2. Rolling Deployment

Application runs below capacity

Bucket size can be configured

Old & new versions run simultaneously

No extra cost

Longer deployment

Flow:

v1 --> stop --> v2 --> v2
v1 --> stop --> v2 --> v2
v1 --> v1 --> v1 --> stop --> v2
v1 --> v1 --> v1 --> stop --> v2

3. Rolling With Additional Batches

Application remains at full capacity

Uses new temporary batch

Slight additional cost

Additional batch removed later

Best for production

Longer deployment

Flow:

v1 --> v1 --> stop --> v2 --> v2 --> v2
v1 --> v1 --> stop --> v2 --> v2 --> v2
v1 --> v1 --> v1 --> v1 --> stop --> v2
v1 --> v1 --> v1 --> v1 --> stop --> v2
new --> v2 --> v2 --> v2 --> v2 --> v2 --> terminated
new --> v2 --> v2 --> v2 --> v2 --> v2 --> terminated

4. Immutable Deployment

Zero downtime

Deploys new code to new instances in temporary ASG

High cost (double capacity)

Safest & quickest rollback

Best for production

-------------------- Nginx Configuration Example --------------------

Edit config:

sudo nano /etc/nginx/sites-available/my_secure_site.conf


Example:

server {
   listen 443 ssl;
   server_name example.com;

   ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
   ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

   ssl_protocols TLSv1.2 TLSv1.3;
   ssl_prefer_server_ciphers on;

   ssl_ciphers 'TLS_AES_128_GCM_SHA256:TLS_AES_256_GCM_SHA384:ECDHE-RSA-AES256-GCM-SHA384';
   ssl_dhparam /etc/ssl/certs/dhparam.pem;

   error_log /var/log/nginx/error.log;
   access_log /var/log/nginx/access.log;

   location /QA/ {
       proxy_pass http://127.0.0.1:8983/;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
   }

   location /dev/ {
       proxy_pass http://127.0.0.1:8993/;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
   }

   location /prod/ {
       proxy_pass http://127.0.0.1:8973/;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
   }
}

server {
   listen 80;
   server_name example.com;
   return 301 https://$host$request_uri;

-------------------------- SSH Key Setup for GitHub Actions --------------------------

Generate SSH Key (Local Machine)
ssh-keygen -t rsa -b 4096 -C "github-deploy" -f deploy_key


This creates:

deploy_key → private key

deploy_key.pub → public key

ssh -i /path/to/key.pem ubuntu@<server-ip>


Create .ssh folder (if not present):

mkdir -p ~/.ssh


Add the public key:

echo "ssh-rsa <public-key> github-deploy" >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
